================================================================================
ROF 曲线  ROFCurve.*  武器键
—— 两版用法说明（同一个功能，两个发布版本）
    第一版：Phobos-LWModified（fork 分支原版）
    第二版：VentureLW（独立注入平台）
================================================================================

【本文件为什么分两版】
  ROF 曲线的 7 个武器键、公式、默认值在 fork 与平台上是**同一套**；但两版的
  「总开关」、可用的组合（扫射/冻结冷却驱动）、DiskLaser 武器是否生效、存档行为
  与日志位置**不一样**。照 fork 的旧说明去配平台、或反过来，都会踩到"看起来没生效"
  的坑。所以下面先给一张差异速查表，再分两版说明。

================================================================================
【第一版】Phobos-LWModified（fork 分支）用法
================================================================================

■ 1.1 开关

  没有全局开关：功能随 fork 的 Phobos.dll 编译进去即生效，只要武器段写了
  `ROFCurve=yes` + `ROFCurve.End` 就会用曲线。

■ 1.2 键值（与第二版相同，全文见附录 A）

  [SOMEWEAPON]                 ; 武器段（WeaponType），不是弹头段
  ROFCurve=no                  ; yes/no，默认 no（不写 = 不启用）
  ROFCurve.Start=              ; 帧数，不写 = 武器自身 ROF
  ROFCurve.End=                ; 帧数，**必填**；不写 = 当作没开曲线
  ROFCurve.Ramp=30             ; 帧数，≤0 回退 30
  ROFCurve.Power=1.0           ; 浮点，夹到 [0.1, 10.0]
  ROFCurve.Decay=0             ; 帧数，0 = 停火立刻退回 Start
  ROFCurve.Cycle=no            ; yes = 到顶后回到 Start 重走

■ 1.3 fork 版特有的两条"冷却驱动"（平台暂不可用）

  在同一把武器**同时**满足条件时，曲线还会按同一比例缩放两个冷却：

  ┌────────────────────┬────────────────────────────────────────────────────────┐
  │ SweepFire 的冷却   │ 武器写 ROFCurve=yes **且** SweepFire.Enable=yes        │
  │                    │ 缩放对象 = SweepFire.Cooldown（扫射时长不变）          │
  ├────────────────────┼────────────────────────────────────────────────────────┤
  │ Temporal 的间隔    │ 武器写 ROFCurve=yes **且** 弹头写 Temporal.Duration>0  │
  │                    │ 缩放对象 = Temporal.Interval（冻结时长不变）           │
  └────────────────────┴────────────────────────────────────────────────────────┘

  例（扫射，ROF=8、Cooldown=60，曲线比例 0.25→3）：
    ROFCurve.Start=2 / End=24 / Ramp=300 / Decay=45
    ⇒ 两次扫射之间的冷却 ≈ 15 → 38 → 73 → 127 → 180 帧，逐次变长

  例（冻结，ROF=100、Interval=30，曲线比例 0.5→2）：
    ROFCurve.Start=50 / End=200 / Ramp=300 / Decay=30
    ⇒ 两次冻结之间的间隔 ≈ 15 → 26 → 38 → 51 → 60 帧，逐次变长

  ⚠ 基数键不能是 0（比例法乘 0 还是 0）；Ramp 要跟"一次攻击周期"相配。
  ⚠ **这两节只在 fork 成立。** VentureLW 尚未迁移 SweepFire 与改进版 Temporal，
    平台版目前只有普通开火间隔会跟随曲线（见第二版 2.3）。

■ 1.4 fork 版的行为边界

  · **DiskLaser=yes 的武器曲线不生效**（fork 在 `0x6FE4B0` 分支把 EBX 当武器类型，
    而该分支 EBX 已是 DiskLaserClass* ⇒ 查不到曲线配置、静默跳过）。这是 fork 的
    已知 bug，不是配置问题；平台版已修正。
  · 7 个键的字段随武器类型扩展**进存档**（fork 的扩展系统）；曲线进度本身不存档。
  · 日志在 `debug.log`：`[Developer warning][<武器名>] ...`（Ramp/Power 修正时）。
  · 没有极端数值的溢出保护：`ROFCurve.End` 写得极大 + 引擎装填很大时，理论上
    乘法结果可能溢出（正常配置不会碰到）。
  · 升级/部署核对：看导出里有没有 `TechnoClass_FireAt_ROFCurve` 之类 handler
    （fork 的核对方式是 `llvm-readobj --coff-exports`）。

■ 1.5 fork 版验证要点

  1) 写的武器连续开火：间隔连续变化（不是换武器、不是台阶）。
  2) 停火后退回：Decay>0 按时间退，Decay=0 立刻回 Start。
  3) 反向曲线（Start>End）越打越慢。
  4) 主/副武器（含弹药逻辑自动切枪）两条进度互不影响。
  5) 扫射武器 + 曲线：两次扫射之间的冷却跟着变（本轮平台版无此项）。


================================================================================
【第二版】VentureLW（独立注入平台）用法
================================================================================

■ 2.1 总开关（两版最大差别）

  [Features]
  ROFCurve=yes      ; 默认 yes。no = 整个模块不动作（所有武器恢复原射速，A/B 排查用）

  即：**平台版多了一个功能总开关**，fork 版没有。关掉它不需要重启存档——下次启动生效。
  注意：这个开关只管"模块"，具体哪把武器生效仍由武器段的 `ROFCurve=yes` 决定
  （两版一致：不写 `ROFCurve=yes` + `ROFCurve.End` 的武器完全不受影响）。

■ 2.2 键值（与第一版相同，全文见附录 A）

  把 fork 的武器段整段搬过来即可：
  [SOMEWEAPON]
  ROFCurve=yes
  ROFCurve.End=6
  ROFCurve.Ramp=60
  ROFCurve.Power=2.0
  ROFCurve.Decay=45
  ROFCurve.Cycle=no

  ⚠ 布尔值写 `yes/no`（`true/false`、`1/0` 也可）。**不要写 on/off**：引擎的
    rules INI 布尔解析只看首字符，on/off 会被当成"没写"而落回默认 no。
  ⚠ `ROFCurve.End` 必填；只写 `ROFCurve=yes` 而没有 End 的武器保持原射速，
    平台日志会额外给一条 warning 提醒（fork 是静默）。

■ 2.3 平台版行为边界（与第一版不同的地方）

  1) **没有"曲线驱动冷却"**：SweepFire 与改进版 Temporal 体系尚未迁到本平台
     （计划 R17 / R19 / R20），所以现在曲线**只影响普通开火间隔**；
     写 `SweepFire.Cooldown` / `Temporal.Interval` 相关的曲线组合，冷却部分不会有变化
     （那些键本身也还不存在）。
  2) **DiskLaser=yes 的武器也生效**：平台版在两条开火分支上取武器的方式一致
     （用 `TechnoClass::Fire_At` 自己的武器槽参数），fork 的那个取值 bug 已修正。
  3) **0 存档变更**：本功能不写任何存档数据（7 个键每次启动从 rules 读；曲线进度
     不存档，读档从 0 开始）。跨版本存档本来就不互通（平台连自己的存档 ID 都不同）。
  4) **极端数值有溢出保护**：`End` 极大 + 引擎装填很大时，结果饱和到最大帧数，
     不会溢出成负数。
  5) **日志在 `VentureLW.log`**：
     · `[ROFCurve] initialized (enabled=1, weapons=N)`
     · DEBUG 级：`[ROFCurve] <武器>: curve usable (start=.. end=.. ramp=.. power=.. ...)`
     · INFO 级（每次进程前 8 条）：`[ROFCurve] <武器>: rearm N -> M frames (ratio ...)`
     · Ramp/Power 修正、End 缺失：`[ROFCurve] <武器>: ...` 的 warning。
  6) 与官方 Phobos / Ares 共载：曲线在**两个开火点**直接改写引擎算好的装填值，
     与官方 Phobos 的 `DEFINE_HOOK` 不冲突（地址不同）；类型键从 rules 读取，
     不与任何宿主共享同名键。

■ 2.4 平台版验证要点

  1) 启动日志有 `[ROFCurve] initialized (enabled=1, ...)`。
  2) 写的武器连续开火：间隔连续变化；日志出现 `rearm N -> M frames (ratio ...)`。
  3) 停火后按 Decay 回落 / 立刻回落；Cycle 到顶行为正确。
  4) 主/副武器（含弹药逻辑自动切枪）两条进度互不影响（B18 判据）。
  5) `[Features] ROFCurve=no` 时全部恢复原射速（A/B 对比）。
  6) 存档/读档后曲线从 0 开始（不报错、不影响其它功能）。
  7) 与 Ares + 官方 Phobos 共载时行为不变（本平台的目标环境）。

■ A.1 键值表（全部写在 **武器段**，即 WeaponType，不是弹头段）

  ┌────────────────────┬───────────────────────┬──────────┬──────────────────────────┐
  │ 键                 │ 取值                  │ 默认     │ 说明                     │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve=          │ yes / no              │ no       │ 总开关。no/不写 = 完全   │
  │                    │                       │          │ 不受影响                 │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve.Start=    │ 帧数（整数）          │ 不写 =   │ 进度 0 那一端。哪端快由  │
  │                    │                       │ 武器自身 │ 你定，不必须比 End 慢    │
  │                    │                       │ 的 ROF   │                          │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve.End=      │ 帧数（整数）          │ **必填** │ 进度 100% 那一端；不写 / │
  │                    │                       │          │ 小于 1 = 没开曲线        │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve.Ramp=     │ 帧数（整数）          │ 30       │ Start → End 用多少帧；≤0 │
  │                    │                       │（2 秒）  │ 回退到 30                │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve.Power=    │ 浮点数                │ 1.0      │ 过渡形状：1.0 直线、>1   │
  │                    │                       │          │ 先慢后快、<1 一开打就快；│
  │                    │                       │          │ 夹到 [0.1, 10.0]         │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve.Decay=    │ 帧数（整数）          │ 0        │ 停火后多少帧退回 Start； │
  │                    │                       │（立刻）  │ 0 = 立刻退回             │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve.Cycle=    │ yes / no              │ no       │ 到顶后：no 停在 End；    │
  │                    │                       │          │ yes 回 Start 重走一遍    │
  └────────────────────┴───────────────────────┴──────────┴──────────────────────────┘

■ A.2 公式

    p     = 进度 0..1（开打第一发是 0）
    ease  = p 的 ROFCurve.Power 次方
    曲线ROF = Start + (End - Start) * ease
    实际装填 = 引擎算出的装填 × 曲线ROF / 武器自身ROF   （至少 1 帧）

  ⇒ 引擎原有修正（AttachEffect 的 ROF 倍率、老练度、ROF.RandomDelay、狂暴减半）
    全部保留，只改节奏本身。`Burst>1` 时改的是"两轮之间"，不是一轮内发间隔。

■ A.3 Power 三档实际数值（正向：ROF=24 → End=6）

  ┌────────────┬──────┬──────┬──────┬──────┬──────┐
  │ 进度       │ 0%   │ 25%  │ 50%  │ 75%  │ 100% │
  ├────────────┼──────┼──────┼──────┼──────┼──────┤
  │ Power=2.0  │ 24   │ 23   │ 20   │ 14   │ 6    │
  │ Power=1.0  │ 24   │ 20   │ 15   │ 11   │ 6    │
  │ Power=0.5  │ 24   │ 15   │ 11   │ 8    │ 6    │
  └────────────┴──────┴──────┴──────┴──────┴──────┘

  反向（Start=6 → End=30，越打越慢）：
  ┌────────────┬──────┬──────┬──────┬──────┬──────┐
  │ 进度       │ 0%   │ 25%  │ 50%  │ 75%  │ 100% │
  ├────────────┼──────┼──────┼──────┼──────┼──────┤
  │ Power=2.0  │ 6    │ 8    │ 12   │ 20   │ 30   │
  │ Power=1.0  │ 6    │ 12   │ 18   │ 24   │ 30   │
  │ Power=0.5  │ 6    │ 18   │ 23   │ 27   │ 30   │
  └────────────┴──────┴──────┴──────┴──────┴──────┘

■ A.4 最小可用写法 / 反向写法（两版通用）

  [MyFastGun]
  ROF=24
  ROFCurve=yes
  ROFCurve.End=6
  ROFCurve.Ramp=60
  ROFCurve.Power=2.0
  ROFCurve.Decay=45
  ROFCurve.Cycle=no

  [MySlowDown]
  ROF=30
  ROFCurve=yes
  ROFCurve.Start=6
  ROFCurve.End=30
  ROFCurve.Ramp=90
  ROFCurve.Power=1.0
  ROFCurve.Decay=45

【附录 B：两版共用的判定与坑（一字不差）】
================================================================================

  1) **ROFCurve.End 必填**：不写 / 小于 1 = 当作没开曲线，武器保持原射速。
  2) **只影响"两轮装填之间"**：Burst 武器一轮内部的连发间隔不改。
  3) **停火判定 = 超过"上发期望间隔 + 3 帧"没开火**：按**这把武器自己**的
     上次开火帧算；别的武器开火不算它开火。超时则按 Decay 回落（Decay=0 立刻归零）。
  4) **每把武器一条独立链**：多武器单位（普通↔精英、主↔副、弹药逻辑自动切枪的
     NoAmmoWeapon）互不重置；每把只按自己的 Decay 回落。两把都写曲线时也各自独立。
  5) **进度不存档**：读档后从 0 起算（观感无差别）。
  6) **Ramp/Power 会被修正**：Ramp≤0 → 30 帧；Power 夹到 [0.1, 10.0]（两版都会
     给告警，只是日志位置不同）。
  7) **下限 1 帧**；**狂暴单位**的射速减半叠在曲线结果上。
  8) **联机确定性**：进度只依赖开火帧号与键值，不存档、不发事件；双方读同一存档
     都从 0 起算。
  9) **原版盖特完全独立**：不碰 GattlingValue/档位/武器序列，曲线作用在"当前武器"上。
 10) **AttachEffect ROF 倍率 / ROF.RandomDelay 保留**（RandomDelay 会带来 ±几帧抖动，
     曲线看起来不会完全平滑）。
