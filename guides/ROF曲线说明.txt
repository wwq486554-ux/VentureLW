================================================================================
ROF 曲线  ROFCurve.*  武器键（VentureLW 平台自有逻辑）
（同一把武器越打越快 / 越打越慢 —— 只改装填间隔，不换武器）
================================================================================

【本文件是给改 INI 的人看的】
  键名、取值范围、默认值、可用组合、示例段、坑与限制都在这里。
  实现与引擎注入点的说明见 docs/New-or-Enhanced-Logics.md。


================================================================================
【一、一句话】
================================================================================

  在任意武器段写 ROFCurve=yes + ROFCurve.End=…，这把武器就会"越打越快"
  （或越打越慢）：从起始射速连续过渡到末端射速，停火后按配置退回去，
  到顶可以停住也可以重走一遍。

  · 方向由你定：把两端倒过来写就是"最开始最快、之后越来越慢"。
  · 全程都是同一把武器，只是"这一发到下一发之间等多少帧"在变 ——
    抛射体、开火动画、音效、弹头、伤害一律不变。
  · **多武器单位各自独立**：同一台单位带多把武器时（主/副、普通/精英、
    弹药逻辑自动切到的副武器），每把武器各攒一条进度 —— 一把武器开火
    不会重置另一把的进度。
  · 总开关是 [Features] ROFCurve（默认开）；具体哪把武器生效由武器段自己
    决定（不写 ROFCurve=yes 的武器完全不受影响）。


================================================================================
【二、它和原版盖特的区别】
================================================================================

  原版盖特（IsGattling / WeaponStages / RateUp / RateDown）把节奏写在**单位**上：
  随时间升档，每升一档就**换一把更快的武器**。所以：

    - 档数取决于你准备了几把武器，节奏是**台阶式**的；
    - 一个单位只能有一套盖特节奏；
    - 想给"任意武器"加这个特性，得为它准备一整列武器。

  ROFCurve 写在**武器**上：同一把武器自己加速，过渡是**连续的**（没有台阶），
  每把武器可以有各自的曲线，也不需要任何额外的武器槽。

  ⇒ 两套东西完全独立，互不干扰；盖特单位照旧换武器，ROFCurve 只作用在
    "当下手里这把武器"上。

【三、键值表（全部写在 **武器段**，即 WeaponType，不是弹头段）】
================================================================================

  ┌────────────────────┬───────────────────────┬──────────┬──────────────────────────┐
  │ 键                 │ 取值                  │ 默认     │ 说明                     │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve=          │ yes / no              │ no       │ 总开关。no/不写 = 与不加 │
  │                    │                       │          │ 这些键完全一样           │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve.Start=    │ 帧数（整数）          │ 不写 =   │ 进度 0 的那一端（刚开打  │
  │                    │                       │ 武器自身 │ 时用哪个射速）。哪端快由 │
  │                    │                       │ 的 ROF   │ 你定，不必须比 End 慢    │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve.End=      │ 帧数（整数）          │ **必填** │ 进度 100% 那一端。       │
  │                    │                       │          │ 不写 / 小于 1 = 当作没   │
  │                    │                       │          │ 开曲线，保持原射速       │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve.Ramp=     │ 帧数（整数）          │ 30       │ 从 Start 走到 End 要多少 │
  │                    │                       │（2 秒）  │ 帧；≤0 回退到 30         │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve.Power=    │ 浮点数                │ 1.0      │ 过渡形状（幂次）：       │
  │                    │                       │          │ 1.0 = 匀速直线           │
  │                    │                       │          │ >1 = 先慢后快            │
  │                    │                       │          │ <1 = 一开打就明显变快    │
  │                    │                       │          │ 超出 [0.1, 10.0] 会被夹  │
  │                    │                       │          │ 住（日志有告警）         │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve.Decay=    │ 帧数（整数）          │ 0        │ 停火后多少帧退回 Start。 │
  │                    │                       │（立刻）  │ 0 = 一停火就立刻退回     │
  ├────────────────────┼───────────────────────┼──────────┼──────────────────────────┤
  │ ROFCurve.Cycle=    │ yes / no              │ no       │ 到顶之后：               │
  │                    │                       │          │ no  = 停在 End           │
  │                    │                       │          │ yes = 回到 Start 重走一遍│
  └────────────────────┴───────────────────────┴──────────┴──────────────────────────┘

  ⚠ 计时单位是**逻辑帧**（RA2/YR 逻辑 15 帧/秒）。所以 30 帧 = 2 秒，45 帧 = 3 秒。

  ⚠ 布尔值请写 yes / no（true/false、1/0 也可以）。**不要写 on / off**：
    引擎的 rules INI 布尔解析只看首字符，on/off 会被当成"没写"而落回默认 no。


================================================================================
【四、公式（想知道具体某一发是多少帧时看这里）】
================================================================================

    p     = 进度，0..1（开打第一发是 0）
    ease  = p 的 ROFCurve.Power 次方
    曲线ROF = Start + (End - Start) * ease

  然后把这个"曲线ROF"按比例套到引擎已经算好的装填时间上：

    实际装填 = 引擎算出的装填 × 曲线ROF / 武器自身ROF        （至少 1 帧）

  ⇒ 引擎原本的所有修正（AttachEffect 的 ROF 倍率、老练度、ROF.RandomDelay）
    都原样保留，只改变节奏本身。狂暴单位的"射速减半"也照旧叠在上面。

  ⚠ 注意：ROFCurve 只改**两次开火之间**的间隔；Burst>1 的武器是"两轮之间"
    的间隔，不是一轮内的发间隔。


================================================================================
【五、最小可用写法】
================================================================================

  [MyFastGun]              ; 武器段，名字自定
  ROF=24                   ; 不写 ROFCurve.Start 时，这就是起点
  ROFCurve=yes
  ROFCurve.End=6           ; 打到最快：每 6 帧一发
  ROFCurve.Ramp=60         ; 4 秒走完加速
  ROFCurve.Power=2.0       ; 先慢后快
  ROFCurve.Decay=45        ; 停火后 3 秒退回 24
  ROFCurve.Cycle=no

【六、Power 三档的实际数值（ROF=24 → End=6）】
================================================================================

  ┌────────────┬──────┬──────┬──────┬──────┬──────┐
  │ 进度       │ 0%   │ 25%  │ 50%  │ 75%  │ 100% │
  ├────────────┼──────┼──────┼──────┼──────┼──────┤
  │ Power=2.0  │ 24   │ 23   │ 20   │ 14   │ 6    │
  │ Power=1.0  │ 24   │ 20   │ 15   │ 11   │ 6    │
  │ Power=0.5  │ 24   │ 15   │ 11   │ 8    │ 6    │
  └────────────┴──────┴──────┴──────┴──────┴──────┘

  想调参就照这张表挑 Power：想要"打久了突然爆发"用 2.0；
  想要"一开打就明显变快"用 0.5。


================================================================================
【七、反向使用：最开始最快，之后越来越慢】
================================================================================

  把两个值倒过来写就行，不需要任何额外的键：

  [MySlowDown]
  ROF=30
  ROFCurve=yes
  ROFCurve.Start=6        ; 进度 0 = 刚开打：每 6 帧一发（最快）
  ROFCurve.End=30         ; 进度 100% = 打久了：每 30 帧一发（最慢）
  ROFCurve.Ramp=90        ; 6 秒走完
  ROFCurve.Power=1.0
  ROFCurve.Decay=45


================================================================================
【八、多武器单位（B18）】
================================================================================

  · 链是按**武器类型**分开存的，不是按槽位：两把不同武器（主/副、主/精英、
    弹药逻辑切到的备用武器）各有各的进度，互不影响。
  · 两个槽指向**同一把武器**时共享一条链（同一把武器本来就是一个节奏）。
  · 一把武器没开曲线时，它开火**不会**创建链、也不会重置另一把武器的进度。
  · 链**不进存档**：读档后每条曲线从 0 开始（视觉上也正是"重新开打"）。


================================================================================
【九、坑与限制（照顺序看）】
================================================================================

  1. **End 必填**。只写 ROFCurve=yes 不写 End 的武器会被当成"没开曲线"，
     保持原射速；平台日志里会有一条 warning 提醒。
  2. **on/off 不生效**（见第三节），请写 yes/no。
  3. Power 超出 [0.1, 10.0] 会被夹住并在日志里告警；Ramp≤0 回退 30。
  4. 引擎算出来的装填小于 1 帧的武器不会被缩放（本来就没有可缩放的间隔）。
  5. 曲线只按"两发之间的真实帧差"推进：引擎把射击压后（例如目标已死/在等
     冷却）时，进度会跟着真实时间走；因此 Ramp/Decay 是**实际时间**意义上的
     帧数，不是你数"开了多少发"。
  6. 连续判定有 3 帧余量：上一发之后 `期望间隔 + 3` 帧内再开火算同一条曲线，
     超出则按 Decay 回落（Decay=0 立即归零）。极低帧率下这个余量的判定可能
     出现细微差异——这也是联机时唯一需要留意的点。
  7. DiskLaser=yes 的武器（如光棱系）同样可用 —— 平台版在这条分支上修正了
     fork 的一个取值 bug，两边行为以本平台为准。
  8. 本平台尚未迁移 SweepFire / 改进版 Temporal（它们会复用同一条曲线驱动
     各自的冷却），所以现在曲线只影响普通开火间隔；等那两项落地后同一套键
     会自动接管它们的冷却，届时本文档会更新。
  9. 总开关 [Features] ROFCurve=no 时整个模块不动作（所有武器恢复原射速），
     适合做 A/B 对比排查。


================================================================================
【十、验收清单（改完 INI 想确认生效时）】
================================================================================

  □ 武器段写了 ROFCurve=yes 与 ROFCurve.End=…
  □ 单位连续开火时射速/节奏按曲线变化（不是台阶式换武器）
  □ 停火超过 Decay 帧后重新开打，从 Start 重新加速
  □ 主/副武器（或弹药逻辑切到的武器）分别连续开火时，两条进度互不影响
  □ 不写 ROFCurve 的武器行为与改之前完全一致
  □ 日志（VentureLW.log）里出现 "[ROFCurve] <武器名>: curve usable (...)"
    以及首次缩放时的 "rearm N -> M frames (ratio ...)"
  □ 存档/读档后曲线从 0 开始（不报错、不影响其它功能）
