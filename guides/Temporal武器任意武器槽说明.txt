================================================================================
Temporal（超时空/传送）弹头支持任意武器槽
—— 两版用法说明（同一个功能，两个发布版本）
    第一版：Phobos-LWModified（fork 分支原版）
    第二版：VentureLW（独立注入平台）
================================================================================

【本文件为什么分两版】
  "任意槽 Temporal" 修的是**原版引擎的两个缺陷**（崩溃 + 抹除速率用错武器），
  两版修出来的**用户可见行为一致**；但两版的**开关位置**、**速率修复的精确度**、
  **存档影响**与**日志**不同，而且旧指南里的示例（`SpecialAction=Weapon`）依赖
  其它功能——那些功能在平台上还没迁移。照旧说明去配平台会找不到键。所以分两版写。

================================================================================
【第一版】Phobos-LWModified（fork 分支）用法
================================================================================

■ 1.1 开关（fork 特有）

  [General]
  TemporalWeapon.AnySlot=true     ; 默认 true

  · true（默认）：Temporal 弹头在任意武器槽都可用；抹除速率也用真正开火的那把武器。
  · false：**完全回到原版行为 —— 包含崩溃本身**，以及按"引擎当前武器"算抹除速率的老
    行为。只用于 A/B 隔离排查。
  · 该布尔值**进入 ExtData 序列化**（fork 的存档布局因此变过一次；跨版本旧档不保证可读）。

■ 1.2 怎么用（fork 示例）

  Temporal 弹头可以放在**任意武器槽**：

  [MYUNIT]
  Weapon1=SomeNormalGun
  Weapon2=SomeNormalGun2
  Weapon3=AnotherGun
  Weapon4=NeutronCannon      ; 弹头 Warhead=ChronoWarpWH（Temporal=yes）
  MultiWeapon=true
  WeaponCount=4
  SpecialAction=Weapon,3     ; 技能强制打槽 3（= Weapon4），不再崩

  要点：
  · 「槽 N」从 0 开始：槽 0 = Weapon1，槽 3 = Weapon4。
  · `WeaponCount` 决定引擎自己会用到几个槽；`SpecialAction=Weapon,N` 直接点名某槽、
    会绕过 WeaponCount —— 这正是当初踩坑的入口。
  · 只想要"能正常打这把武器"就配好 WeaponCount；纯 Chrono 单位仍推荐把 Temporal
    放 Weapon1/主武器（原版唯一保证的路径）。
  · 不需要其它键：不给单位加 Temporal=yes，也不改 art。

■ 1.3 fork 版的速率口径

  修复在 fork 自己的 `TemporalClass::GetWarpPerStep` 替换实现里：引擎选中的武器
  （Ares 下读 `WeaponIndex_Warp`，否则 `SelectWeapon`）**没有 Temporal 弹头**时，
  改用"这一发真正开火的武器"——**Damage 与 Warhead 一起换**，所以
  `Temporal.ApplyMultiplier` / `Temporal.ApplyVersus` / `Deployed` / `ProneDamage`
  也一并对齐到真正开火那把武器的弹头。

■ 1.4 fork 版边界（详见附录 B，另加两条 fork 特有）

  · 记录是"每单位一个、只记最近一次"：同一单位配两把不同 Temporal 武器交替打两个
    目标时，后一次会覆盖记录（两把都是 Temporal 时影响很小）。
  · 部署核对：看导出里有没有 `BulletClass_Detonate_EnsureTemporal`（fork 的核对方式
    是 `llvm-readobj --coff-exports`；fork 各版本的导出总数不同，别记死数字）。

■ 1.5 fork 版验证清单

  1) 复现原始崩溃配置（`[LWCOLD]`：WeaponCount=3 + `SpecialAction=Weapon,3`）→ 按键
     不再崩，且目标**几乎瞬间被抹除**（2100 ÷ 1000 ≈ 3 帧量级），不是"慢慢吸"。
  2) 连打多发：复用同一个 Temporal 实例，速度同样快。
  3) 原版 `[CLEG]` / `[chrtnk]` 行为逐项不变。
  4) helper 链（多台 Chrono 单位同时打同一目标）行为不变。
  5) 把 `TemporalWeapon.AnySlot` 改成 no 重开 → 应能复现原崩溃（证明开关有效）。

【第二版】VentureLW（独立注入平台）用法
================================================================================

■ 2.1 开关（平台版：没有 [General] 键！）

  [Features]
  TemporalAnySlot=yes      ; 默认 yes

  · **平台没有 `[General] TemporalWeapon.AnySlot` 这个键**，不要去 rules 里找/写它；
    写了也不会被本平台读取（可能被其它宿主读到）。
  · yes（默认）：任意槽 Temporal 可用 + 抹除速率按真正开火的武器走。
  · no：完全原版行为——**包括崩溃本身**（只用于 A/B 排查）。
  · **0 存档变更**：本功能不往存档写任何东西（对比 fork 的开关布尔进存档）。

■ 2.2 怎么用（平台示例）

  INI 侧和 fork 完全一样（Temporal 弹头放任意武器槽即可），**唯一的差别是开关在
  `VentureLW.ini` 的 `[Features]` 段，不在 rules 的 `[General]` 段**：

  [MYUNIT]
  Weapon1=SomeNormalGun
  Weapon2=SomeNormalGun2
  Weapon3=AnotherGun
  Weapon4=NeutronCannon      ; 弹头 Warhead=ChronoWarpWH（Temporal=yes）
  MultiWeapon=true
  WeaponCount=4

  VentureLW.ini：
  [Features]
  TemporalAnySlot=yes

  ⚠ **平台当前还没有迁移 SpecialAction（计划 R7）**，所以 fork 示例里的
    `SpecialAction=Weapon,3` 触发方式在本平台暂时用不了。现在验证"任意槽"请用
    **副武器 / 多武器槽**等引擎本来就会走到的路径：把 Temporal 弹头放在副武器，
    让单位用副武器攻击（右键目标时引擎会选它），或按 Ares 的武器能力（如适用）触发。
    等 R7 迁移完成后，旧示例可直接使用（届时本文档更新）。

■ 2.3 平台版速率口径（与 fork 的差别）

  平台不能替换 `TemporalClass::GetWarpPerStep`（官方 Phobos 已整函数占用
  `0x71AB10`；Ares 还会把 `TemporalClass::Update` 的中段整段跳过），所以：

  · 注入点 `0x71AB08`（`TemporalClass::Update` 的公共尾板，vanilla 与 Ares 两条路径
    都经过）按链逐节点把**引擎本帧算出的步长**按 `记录武器 Damage ÷ 引擎选中武器
    Damage` 的比例校正 `Remaining`；
  · 引擎选中的武器本身就是 Temporal 弹头时**完全不干预**（原版 Chrono 单位、
    Ares `WeaponIndex_Warp` 用法不变）；
  · **已知精度边界**：这是**按比例**校正，保留引擎（含共载官方 Phobos）已经算进去的
    `Temporal.ApplyMultiplier` / `ApplyVersus` 等**弹头级乘数**的效果，只是把
    "武器 Damage" 换成真正开火那把；fork 是整函数重算（连弹头一起换）。所以：
      - 正常情况下（这些乘数为默认/无）两版结果一致；
      - 若共载的官方 Phobos 开了 Temporal 乘数相关键、且"选中的武器"与"真正开火的
        武器"弹头类型不同，两版会有细微差别（速率仍按真正开火武器的 Damage 走）。
  · 平台**不写** Ares 内部字段；Ares 宿主下按官方口径**只读** `WeaponIndex_Warp`
    作为"引擎选中槽"（Ares 不在时回落 `SelectWeapon`）。

■ 2.4 平台版边界（另加两条）

  · **未迁移** Temporal CellSpread（fork 的 B11，计划 R19）：`Temporal=yes` 弹头写了
    `CellSpread` 时，平台的"半径内每人各冻一个"不会发生（按原版单目标处理）。
  · 记录同样是"每单位一个、只记最近一次"（与 fork 相同，见附录 B）。

■ 2.5 平台版日志

  · `[TemporalAnySlot] initialized (enabled=1, ares=1)`（启动块）
  · DEBUG：Ares 扩展指针为空等防御信息
  · INFO（每次进程前 8 条）：`[TemporalAnySlot] warp rate corrected: TemporalClass
    0x........, N node(s), WarpRemaining +X -> Y`

■ 2.6 平台版验证清单

  1) 启动日志有 `[TemporalAnySlot] initialized (enabled=1, ares=1)`、
     `startup complete - 6 feature(s) registered`。
  2) 用**非第一槽**的 Temporal 弹头（副武器路径）打一个单位：**不崩**、目标被抹除，
     且抹除速度符合该武器 Damage（不是主武器的慢速）。
  3) 原版 `[CLEG]` / Chrono Tank 行为逐项不变（抹除节奏、光标、解冻、音效）。
  4) helper 链（多台 Chrono 单位打同一目标）行为不变。
  5) `[Features] TemporalAnySlot=no` 后重开 → 回到原版行为（可复现崩溃，仅排查用）。
  6) 日志出现 `warp rate corrected` 行可佐证速率校正生效。
  7) Ares + 官方 Phobos 共载下重复 2)–3)（本平台目标环境）。


================================================================================
【附录 A：两版共用的根因与修复（一句话版）】
================================================================================

  1) 引擎只在 `TechnoClass::Init` 里、且**只看武器槽 0** 的弹头是否为 `Temporal=yes`
     时创建 `TemporalImUsing`；Temporal 弹头从别的槽落地时 `0x4694BB` 直接拿它当
     `this` 调 `TemporalClass::Fire`、**不判空** → 崩在 `0x71AF4D`。
     两版都在 `0x4694BB`（弹头落地、引擎 Fire 之前）按需补建实例，一处覆盖所有路径。
  2) 抹除速率取自"单位当前选中的武器"，强制槽/任意槽开火后选择已释放 → 按主武器
     Damage 慢慢抹。两版都记录"真正开火的那把武器"并修正速率（实现位置不同，见
     各版 1.3 / 2.3）。
  3) 两版都不改变：一个单位只有一个 Temporal 实例、helper 链的叠加、LetGo/解冻规则、
     原版 Chrono 单位路径。


================================================================================
【附录 B：两版共用的边界与注意（一字不差）】
================================================================================

  1) 一个单位只有【一个】Temporal 实例，Temporal 武器开火时**复用**它——引擎设计，
     两版都不改。
  2) 修复只解决 Temporal；同一门控下的 MindControl(+0x155) / Parasite(+0x159)
     **没有一起改**（原记录里那两条只是推定）。
  3) `gamemd.edb` 那条已知崩溃还提到"碎片武器发射 / 从有人建筑城市战发射"两种场合；
     两版都在**弹头落地层**兜底，只要走到 Temporal 落点分支就一并覆盖。
  4) 记录是"每单位一个、只记最近一次"：同一单位两把不同 Temporal 武器交替打两个目标，
     后一次覆盖前一次（两把都是 Temporal 时影响很小）。
  5) 只有"引擎选中的武器**没有** Temporal 弹头"时才换成记录的那把——原版 Chrono 单位、
     Ares `WeaponIndex_Warp` 的既有行为不受影响。
  6) 确定性：命中在同步模拟内、TemporalClass 构造不抽随机数 ⇒ 各机同帧建同一实例，
     联机不掉线（两版一致）。
